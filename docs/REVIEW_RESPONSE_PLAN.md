# 2026-10-21 初审反馈与扩展目标

初审指出：包含证明与一致性证明的功能范围较窄，三个场景重复使用同一能力，
独立复用价值不足；建议参考 pymerkle、transparency-dev/merkle，补充持久化、
恢复、可扩展构树、批量操作和区间证明。此次据此扩展实现，完成后再修改申报材料。

## 本轮交付

1. **可合并的 compact range**：任意连续区间的规范完整子树集合，验证区间边界，
   合并相邻分片；仅保存 O(log n) 个哈希即可流式计算根，并导出、校验及恢复状态。
   这是构树组件，不能独自生成已经丢弃的历史节点证明。
2. **区间与批量 API**：用共享的区间外哈希证明 `[start,end)` 的所有记录；验证时
   绑定独立可信快照、索引及全部记录；内存批量追加先检查整批限额，失败不修改日志。
   同时提供按完整子树坐标读取的证明生成 API，允许对接外部存储。
3. **native 磁盘日志**：追加保存记录、偏移及完整子树哈希，随机读取生成历史证明，
   不将整棵树载入内存。批量提交同步数据后原子替换检查点；重启恢复检查点及前沿，
   回滚检查点之后的未提交尾部。单写者锁；提交状态不确定时必须关闭重开，不能继续追加。
4. **实际应用与 CLI**：批次数据的区间回执、重启继续写入的事件日志、分片构树与状态恢复。
   分别体现区间数据交付、持久化恢复、可组合构树，提供独立输入输出和失败案例。
5. **验收证据**：小树全部区间穷举、独立参考、故障注入与重启、实际超过 65,536 叶的
   构树/磁盘例子、多后端核心测试、Windows/Linux native 存储测试、资源实测和来源记录。

## 存储与正确性边界

- 核心仍使用 RFC 9162 SHA-256 配置，保留原 alpha API；新证明格式明确标注，
  不将自定义区间证明冒充 RFC 原有线格式。
- 持久化仅支持本地文件系统、单写者；不承诺网络文件系统、数据库事务或多进程并发写。
- 写入后同步文件，再提交检查点；原子替换和目录同步由很小的 native I/O 适配层负责。
  树、证明、序列化校验、提交顺序与恢复逻辑均由 MoonBit 实现。
- 校验和检测损坏，不认证来源。调用方仍须独立保存和认证可信根；提供全量审计检测
  记录、索引与节点内容损坏，不能以恢复成功宣称任意磁盘篡改都已被检查。
- 明确每批、每条记录和文件偏移限额；可扩展是内存随批次/树高增长，
  不是取消所有资源限制，也不声称已有生产用户。
